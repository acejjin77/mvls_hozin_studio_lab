# MVLS HOZIN STUDIO LAB — 프로그램 · 워크숍 신청

링크트리(`linktr.ee/mvlshozinstudio.lab`)의 구글폼 7개를 홈페이지 하나로 옮긴 버전입니다.
프로그램 신청(1회권 · 월 등록 · 영문 1 Time)은 **`LAB 신청내역` 탭 하나**에 쌓이고, 워크숍은 워크숍마다 탭 하나에 쌓입니다. 워크숍은 시트에서 한 줄로 추가 · 삭제합니다.

```
방문자 ─ index.html ──POST──▶ Apps Script 웹앱 ──▶ 구글 시트
                     ◀─GET── (워크숍 목록)            ├ LAB 신청내역           (1회권 · 월 등록 · 1 Time)
                                                     ├ LAB 워크숍_<워크숍ID>   (첫 신청 때 자동 생성)
                                                     ├ LAB 워크숍관리         (직원이 워크숍 추가·삭제)
                                                     └ LAB 현황               (1회권 / 월 등록 / 1 Time / 워크숍별 상태 건수)
```

학원(mvls-web)과 **같은 스프레드시트 파일 · 같은 Apps Script 프로젝트 · 같은 웹앱 URL** 을 씁니다. 탭은 `LAB …` 으로 따로 쌓여 학원 탭(`MVLS-신청내역`, `수업별현황`)과 섞이지 않습니다.

> 웹사이트 · GitHub 저장소는 학원과 따로입니다. 서버 쪽은 학원 Apps Script 프로젝트에 **`Lab.gs` 파일 하나를 추가**하는 방식입니다.

## 신청서 ↔ 화면 ↔ 시트

| 기존 구글폼 | 홈페이지에서 | 저장되는 시트 | 필수 연락처 | 결제 안내 |
|---|---|---|---|---|
| [1회권] · [월 등록] 프로그램 신청서 | **국문 화면 · 신청서 하나** — 프로그램 선택 → 1회권 또는 월 등록 n주 | `LAB 신청내역` (권종 · 언어 KO) | 연락처 | 참여비 · 송금처를 연락처로 안내 |
| [1 Time] Register for Foreigner | **영문(EN) 화면** · **1회권(1 Time)만** 선택 가능 | `LAB 신청내역` (권종 1회권 · 언어 EN) | 인스타그램 | 현장 현금 (금액 표시) |
| [Workshop] 각 워크숍 | 워크숍 카드 → 신청 | `LAB 워크숍_<워크숍ID>` | 국문: 연락처 + 인스타 / 영문: 인스타 | 계좌이체(완료 화면에 LAB 계좌) 또는 현장 현금 |

- 메인 화면 '신청서' 카드는 3개입니다: **[1회권 · 월 등록] 프로그램 신청서** (학원 홈페이지처럼 하나로 통합) / [1 Time] Register for Foreigner (영문 화면으로 전환) / [Workshop].
- 외국인(영문 화면)은 **1회권만** 신청할 수 있습니다. 화면에 월 등록이 보이지 않고, 서버도 영문 신청의 월 등록 · 기간제(4W · FULL)는 거절합니다.
- `LAB 신청내역` 에서 구분: **권종**(`1회권` / `월 등록 4주` …) · **언어**(`KO` / `EN`). 필터로 나눠 보거나 `LAB 현황` 탭에서 건수를 봅니다.
- 한 사람이 여러 프로그램을 신청하면 프로그램마다 한 줄씩 저장됩니다. ("다른 프로그램도 신청하기" 버튼, 이름 · 연락처 자동 입력)
- 국문 1회권 · 월 등록은 기존 폼처럼 **참여비를 화면에 표시하지 않습니다.** 표시하려면 `config.js` 의 `showProgramPriceKo: true`.

## 1. 설치 — 학원 구글 시트 파일에 함께 두기

```
학원 스프레드시트 파일 (하나)
 ├ 탭: MVLS-신청내역 · 수업별현황                  ← 학원
 ├ 탭: LAB 신청내역 · LAB 워크숍_… · …              ← LAB
 └ 확장 프로그램 → Apps Script (프로젝트 하나)
     ├ Code.gs   학원 접수 + "site=lab 이면 Lab.gs 로 넘기기"   ← mvls-web/apps-script/Code.gs
     └ Lab.gs    LAB 접수                                     ← mvls-lab/apps-script/Lab.gs
            │
      웹앱 URL 하나 ─── 학원 홈페이지 config.js / LAB 홈페이지 config.js 에 같은 주소
```

1. 학원 구글 시트 → **확장 프로그램 → Apps Script**
2. **`Code.gs` 교체** — 전체 선택 후 **mvls-web** 의 `apps-script/Code.gs` 최신본 붙여넣기 (LAB 연결 몇 줄이 추가된 버전, `CODE_VERSION` `2026-11-22-mvls-tab`)
   - 학원 탭 이름은 `MVLS-신청내역` 입니다. 시트에서 `신청내역` → `MVLS-신청내역` 으로 직접 바꿔도 되고, 그대로 두면 다음 학원 신청 · 조회 · setup 때 **자동으로 이름만** 바뀝니다. (데이터 · `수업별현황` 수식 유지)
3. **`Lab.gs` 추가** — 왼쪽 '파일' 옆 **＋ → 스크립트** → 이름 `Lab` → **mvls-lab** 의 `apps-script/Lab.gs` 붙여넣기 → 저장
4. 위쪽 함수 선택에서 **`setupLab`** → 실행 → 권한 승인
   - 시트 맨 뒤에 `LAB 신청내역` · `LAB 워크숍관리` · `LAB 현황` 탭이 생깁니다. 학원 탭 · 데이터는 건드리지 않습니다.
   - 예전 버전으로 만든 `LAB 1회권` · `LAB 월등록` · `LAB 1 Time` 탭이 있으면 더 이상 쓰지 않으니 지워도 됩니다. (신청이 들어 있었다면 `LAB 신청내역` 으로 옮긴 뒤)
   - 시트를 새로고침하면 'MVLS' 메뉴에 **LAB 시트 초기 설정** 이 생깁니다. (다음부터는 메뉴로 실행)
5. **재배포 — 새 배포가 아니라 기존 배포 수정**
   - **배포 → 배포 관리 → (기존 배포) ✏ 수정 → 버전: 새 버전 → 배포**
   - 이렇게 하면 웹앱 URL 이 **그대로**라 학원 `config.js` 는 바꿀 필요가 없습니다.
6. **mvls-lab** 의 `assets/config.js` `API_URL` 에 학원 `config.js` 와 **같은 URL** 붙여넣기
7. 확인 — 브라우저로 열어보기
   - `…/exec` → `"service":"mvls-apply"`, `"version":"2026-11-22-mvls-tab"`, `"lab":"2026-11-22-lab-v4"` (학원)
   - `…/exec?site=lab` → `"service":"mvls-lab-apply"` (LAB)
   - `…/exec?site=lab&action=workshops` → 워크숍 목록

| | 학원 | LAB |
|---|---|---|
| 서버 파일 | `Code.gs` | `Lab.gs` (같은 프로젝트) |
| 웹앱 URL | 같음 | 같음 — LAB 홈페이지 요청에는 `site=lab` 이 붙어 구분 |
| 시트 탭 | `MVLS-신청내역`, `수업별현황` | `LAB 신청내역`, `LAB 워크숍_…`, `LAB 워크숍관리`, `LAB 현황` |
| 접수번호 | `MV…` (예: MV261122-001) | `LB…` — 일련번호는 따로 셉니다 |
| 초기 설정 | 'MVLS' 메뉴 → 시트 초기 설정 (`setup`) | 'MVLS' 메뉴 → LAB 시트 초기 설정 (`setupLab`) |
| 알림 메일 (스크립트 속성) | `NOTIFY_EMAIL` | `LAB_NOTIFY_EMAIL` (없으면 `NOTIFY_EMAIL` 로) |

- 중복 접수 방지 · 신청 횟수 제한 · 조회 제한은 학원 · LAB 이 **따로** 셉니다. (서로 영향 없음)
- `Lab.gs` 를 지우면 학원만 동작합니다. (LAB 요청은 학원 탭에 섞이지 않고 `LAB_NOT_INSTALLED` 오류로 거절됩니다)
- `Code.gs` 나 `Lab.gs` 를 고치면 **배포 관리 → 수정 → 새 버전** 으로 다시 배포해야 반영됩니다. (편집기 저장만으로는 웹앱에 반영되지 않음)
- `config.js` 의 `[확인 필요]` 채우기 — 특히 **워크숍 계좌(`payment.workshop`)**

> **참고:** 구글 시트는 탭별로 열람 권한을 나눌 수 없습니다. 시트를 공유받은 직원은 학원 · LAB 신청을 모두 볼 수 있습니다. (명세서 2장의 사업자별 데이터 분리 · 개인정보 처리 주체 검토와 함께 판단)

## 2. GitHub 저장소 — 꼭 확인

`mvls-lab` 폴더는 `mvls-web` 을 복사해서 만들어져, **git 원격 주소가 학원 저장소(`mvls_hozin_studio`)** 로 되어 있습니다.
그대로 push 하면 **학원 홈페이지가 LAB 사이트로 덮어써집니다.**

```bash
cd mvls-lab
# GitHub 에서 새 저장소(예: mvls_hozin_studio_lab)를 만든 뒤
git remote set-url origin https://github.com/<아이디>/mvls_hozin_studio_lab.git
git remote -v   # 학원 저장소가 아닌지 확인 후 push
```

## 3. 워크숍 추가 · 마감 · 삭제 (직원)

구글 시트 **`LAB 워크숍관리`** 탭에서 한 줄 = 워크숍 하나입니다. 저장하는 순간 홈페이지에 반영됩니다. (재배포 불필요)

| 칸 | 입력 | 예 |
|---|---|---|
| 워크숍ID | 영문 소문자 · 숫자 · 하이픈. **한 번 정하면 바꾸지 않기** (신청 탭 이름 `LAB 워크숍_<ID>` 가 됨) | `1128-cio` |
| 상태 | `모집중` 신청 가능 / `마감` SOLD OUT 표시 / `숨김` 홈페이지에서 숨김 | 모집중 |
| 제목 | 카드에 크게 표시 | `CIO` |
| 날짜 | `2026-11-28` (날짜가 지나면 자동으로 숨김) | |
| 장소 | | 마블러스 호진 스튜디오 랩 (…) |
| 포스터 이미지 URL | 선택. `https://` 이미지 주소 (없으면 제목으로 만든 카드) | |
| 안내 (선택) | 카드 · 신청 화면에 작게 표시 | 시간변경 (11/14) |
| 타임1~4 이름 / 시간 / 금액 | 타임이 하나면 타임1만. 금액은 숫자 (쉼표 있어도 됨) | `A (JUNIOR YUDAT…)` / `15:00-18:00` / `120000` |

- **추가**: 맨 아래에 한 줄 입력 → 상태 `모집중`
- **마감**: 상태를 `마감` → 카드에 SOLD OUT, 신청 불가
- **삭제**: 상태 `숨김` 또는 줄 삭제. 이미 받은 신청은 `LAB 워크숍_<ID>` 탭에 그대로 남습니다.
- 첫 신청이 들어오면 `LAB 워크숍_<워크숍ID>` 시트와 `LAB 현황` 탭 줄이 자동으로 생깁니다.
- **금액은 서버가 이 탭 기준으로 다시 계산해 저장**합니다. (홈페이지 화면 값을 믿지 않음)
- 공통 안내문(수납 기한, 입장, 양도, 음료)은 `config.js` 의 `workshopGuide`, 환불 · 개인정보 문구는 `terms.js` 의 `wsRefund` · `wsPrivacy`.

## 4. 고정 신청서 프로그램 바꾸기 (개발자)

`assets/classes.js` 만 수정합니다. (형식은 파일 상단 주석 참고)

- `tickets`: `{ type: '4W', weeks: 4 }` = 4주권, `{ type: '1T', price: 40000 }` = 1회권 (영문 1 Time 에 금액 표시)
- `period`: 기간제 프로그램 — 기간 안에 n주가 모두 들어가는 시작일만 선택 가능, 휴식권 적용 안 됨
- `closures` 휴강(No Program) · `subs` 대강 → 상단 공지와 날짜 선택에 자동 반영

## 5. 직원 운영

- 모든 신청은 `상태: 입금대기` 로 쌓입니다 → `입금확인` → `확정` / `대기` · `취소` · `환불`
- 중복 신청 차단: 같은 연락처(또는 인스타) + 같은 프로그램 · 시작일 / 같은 워크숍 · 같은 타임
- 열 순서는 옮겨도 됩니다 (1행 헤더 이름으로 찾음). 헤더 글자와 탭 이름은 바꾸지 마세요. 옮긴 뒤 'MVLS → LAB 시트 초기 설정' 한 번 실행 → `LAB 현황` 수식 갱신
- 신청내역 조회: 국문은 이름 + 연락처, 영문은 이름 + 인스타그램으로 **모든 시트**에서 찾습니다. (연락처 · 보호자 · 예금주 · 문의 · 관리자메모는 보이지 않음)
- 보호자 연락처(14세 미만): 휴대폰 · 이메일 · 인스타그램 중 하나 — 판단 규칙은 mvls-web README 3-3 과 같습니다.

## 6. 오픈 전 확인할 항목 (`[확인 필요]`)

1. **워크숍 계좌** (`config.js` `payment.workshop`) — 은행 · 계좌번호 · 예금주
2. **LAB 사업자등록번호** (`config.js` `businesses.LAB`)
3. **프로그램 참여비 환불 기준** (`terms.js` `refund`) — 기존 폼에 없어 비워둠
4. 구글폼끼리 내용이 다른 부분
   - YUJIN `ISOLATION TRAINING` — 월등록폼은 기간 9/9~10/28, 1회권 · 1 Time 폼은 진행 중 → 진행 중으로 입력
   - DAM `SOUND & BODY` — ~10/29 종료로 보여 제외
   - MING `MEMPHIS JOOKIN` — 폼 표기 `12/6~2/26` 은 일요일이라 첫 금요일 **12/4** 로 입력 (12/25 · 1/1 휴강 → 11주)
   - MING `MEMPHIS JOOKIN BASIC` (금 18:20) — 1 Time 폼에만 있음 → 1회권만 열어둠
   - 1 Time 폼에 있던 **학원 수업**(TORCH, SKYTUBE, HIDDEN 등)은 결정에 따라 제외 — 학원 홈페이지 영문 신청으로
5. 워크숍 개인정보 동의문에서 '확진자 발생 시 정보 제공' 목적은 뺐습니다. 필요하면 `terms.js` 에 다시 추가
6. `index.html` 의 `og:image` — LAB 사이트 주소가 정해지면 절대 주소로 변경

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 화면 (히어로 · 신청서 카드 · 프로그램 · 워크숍 · 신청 방법 · 신청 / 워크숍 / 조회 창) |
| `assets/app.js` | 프로그램 · 워크숍 신청, 조회, 영상 슬라이드 |
| `assets/config.js` | API 주소, 카카오 · 인스타, 워크숍 계좌 · 안내, 데모 워크숍 |
| `assets/classes.js` | LAB 프로그램 시간표 |
| `assets/terms.js` | 프로그램 · 워크숍 동의 문구 |
| `apps-script/Lab.gs` | LAB 접수 서버 — 학원 Apps Script 프로젝트에 파일로 추가 (LAB 신청내역, 워크숍별 시트, 워크숍관리, 조회) |

`API_URL` 이 비어 있으면 **데모 모드**입니다. 실제 접수 없이 브라우저에만 저장되고, 푸터 '데모 접수내역'에서 어느 시트로 들어갈지 확인할 수 있습니다.
